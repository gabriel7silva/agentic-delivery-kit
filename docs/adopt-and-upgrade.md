# Adopt and upgrade

Two ways to bring the kit into a repository, and how to take a new version later without losing
your edits.

## Copy-out (simplest)

Copy the directories you use into your repository and edit freely. Good for a team that wants
the method and does not care about future kit versions.

You keep: `core/` (read), `templates/` (edit the placeholders or render them), your track's
`setup.md`, `agents/` (edit scopes and floors), and — if you want the gate — `automation/` with
its scripts.

Upgrading later is a manual diff. Fine if you rarely will.

## Vendored at `.pact/` (recommended when you want the gate)

```bash
git subtree add --prefix .pact <kit-remote> main --squash
```

The copy-ready workflows expect this path (`automation/ci/INSTALL.md`). Your own files —
`instance.yml`, `AGENT-CONTEXT.md`, `CURRENT-FOCUS.md`, your workflows — live at your root; the
kit lives under `.pact/`. To upgrade:

```bash
git subtree pull --prefix .pact <kit-remote> main --squash
```

Conflicts land only in files you edited inside `.pact/` — by design that is `agents/ownership.yml`
and `agents/policies/risk-floors.yml`. Resolve them, run `.pact/automation/scripts/check_schemas.py`,
done.

## What changes between versions, and what does not

`VERSION` follows SemVer on the **neutral contract** — the symbols in `core/model/`, the field
set, the state names, the mapping schema. Prose can improve in a patch; a symbol cannot change
meaning without a major.

| Bump | Means | You do |
|---|---|---|
| **patch** | Prose, briefs, guides, examples | Pull. Regenerate adapters if you use one |
| **minor** | A new optional rule, a new capability, a new track, a new field with a default | Pull. Check `CHANGELOG.md` for a new `optional_rules` key you may want |
| **major** | A symbol renamed or removed; a mandatory rule added | Read the changelog's migration note before pulling. Re-run `make mapping` against any track you customised |

Under `0.x` a **minor** may also change a symbol's meaning — `0.3.0` turned `ACTIVE` and `RESOLVED`
into categories and made `topology` a required instance key; `0.4.0` added the sprint-close cadence
keys and the return transition — and then the changelog carries a numbered migration note. Read it before pulling.

## Keep your edits where upgrades expect them

| Yours | Where |
|---|---|
| Names, cadence, roles, board | `instance.yml` at your root — never inside `.pact/` |
| Scopes, floors | `.pact/agents/ownership.yml`, `.pact/agents/policies/risk-floors.yml` — the two files subtree will ask you to merge |
| Agent context | `AGENTS.md`, `AGENT-CONTEXT.md`, `CURRENT-FOCUS.md` at your root; the runtime pointer files, regenerated by `.pact/automation/scripts/entry_points.py --root . --kit .pact` |
| A runtime adapter of your own | `.pact/adapters/<name>/` — a new directory, never a modified one |
| A profile of your own | `.pact/profiles/<name>/` — same |

Anything else you find yourself editing inside `.pact/` is worth a contribution upstream
(`CONTRIBUTING.md`) instead of a private fork.
