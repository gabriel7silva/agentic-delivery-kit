# Glossary

One line per term. If a term needs a paragraph, it has a home in `core/` and this entry links to it.

| Term | Meaning |
|---|---|
| **PACT** | The method: Plan → Act → Check → Transfer. Phases map to the categories `New → Active → Resolved → Closed`. |
| **Source of truth (SoT)** | The one tool where a work item's state is authoritative. Exactly one per instance. Slack can never be it. |
| **Track** | A translation of the neutral model onto one tool (`tracks/<name>/`). Contains no method. |
| **Profile** | An overlay for a context (`agency`, `internal`). May add and configure; may never redefine canon. |
| **Canon** | A rule's single authoritative home in `core/`. Everything else links to it by id. |
| **Fragment** | A block that must leave the repo (e.g. inside a work-item comment) and is therefore copied inline between `canon:begin`/`canon:end` fences, byte-checked against `templates/_fragments/`. |
| **Instance** | Your filled-in `instance.yml`: names, board, cadence, roles. The only file that knows who you are. |
| **Work item** | The unit of tracked work. Types: Epic, Feature, Story (PBI), Task, plus Bug and Issue. |
| **WI-State** | The work item's lifecycle state — twelve by default, each in one of five fixed categories. One axis. `core/05-states.md`. |
| **Category** | One of the five lifecycle groups a WI-State belongs to: `New`, `Active`, `Resolved`, `Closed`, `Removed`. Rules, gates and tracks speak in categories; instances rename or drop states, never categories. |
| **Lifecycle** | The set of WI-States an instance runs, and their labels (`instance.yml` → `lifecycle`). A subset of the model's twelve, at least one per category. |
| **Status** | The board column the item sits in. A *different* axis, translated from WI-State per track. |
| **Resolved ≠ Closed** | Agents may reach `Resolved`. Only a human moves an item to `Closed`. See `core/05-states.md`. |
| **Handoff** | The Definition of Ready made concrete: the brief an orchestrator gives an implementer. `templates/flow/handoff.md`. |
| **Receipt** | The Definition of Done made concrete: what was done, per-AC acceptance, and what was **not** verified. `templates/flow/receipt.md`. |
| **Conclusion comment** | Six mandatory fields posted on the item before any state transition. `core/07-evidence.md`. |
| **Scope** | A named set of path globs with exactly one writer and required reviewers. `agents/ownership.yml`. |
| **Claim** | A record *in the source of truth* that one agent currently owns writes to a scope. One open claim per scope. |
| **Single writer** | The rule that only one agent edits a scope at a time. Readers may be many. `core/09-concurrency.md`. |
| **Review gate** | A required, evidenced review before a transition. Reviewers return findings and a risk verdict. |
| **Risk floor** | The minimum risk level a path carries regardless of what any reviewer says. `agents/policies/risk-floors.yml`. |
| **Human gate** | A transition that requires a named human. Triggered by risk level or by one of the five escalation triggers. `core/03-human-in-the-loop.md`. |
| **Capability** | Something a tool can or cannot do (`code_review`, `ci`, `durable_history`, `sot_eligible`). Rules declare what they require. |
| **Substitute** | For a track lacking a capability: the declared replacement mechanism and the evidence it produces. |
| **Compatibility matrix** | Generated table: rule × track → supported / substituted / unsupported. `docs/compatibility-matrix.md`. |
| **Adapter** | A one-way generator from the neutral roster to one runtime's native config. The only place a runtime is bound to the roster. |
| **Prompt pack** | The adapter that needs no runtime: plain prompts usable in any chat. Proves the roster is neutral. |
| **Honest placeholder** | `- [ ] unknown — …`. The written form of "we do not know yet", used instead of inventing. |
| **Not verified / not claimed** | Mandatory receipt section listing what was *not* checked, so absence of evidence is never mistaken for evidence. |
| **Topology** | Who fills the five roles — people or agents — and who hands work to whom: `agent-to-human`, `agent-to-agent`, `independent-agents`, `bot-team`. `core/15-topologies.md`. |
| **Writing standard** | The one shape every human-facing document takes — hierarchy, tables, ten icons with fixed meaning, the main rule in a box; machine-read fields stay exact. `core/16-writing-standard.md`. |
| **PO assistant** | The advisor agent in the roster: guides people on the method and turns a raw request into a refined specification. Never sets a state. `agents/briefs/po-assistant.md`. |
| **Refined specification** | A Feature with one story per independent deliverable, scenarios, rules to validate, risks, questions and the registration tree. `templates/flow/refined-spec.md`. |
| **Entry point** | `AGENTS.md` at the root — the one file an agent reads first. A pointer file per runtime, generated by `automation/scripts/entry_points.py`, lands on it; runtimes read them only from the folder that was opened. |
| **External reference** | The id of the request in another system, on the `EXTERNAL_REF` field and at the start of the title as `[<ref>]`. Optional rule `require_external_ref`. |
| **Sprint metrics** | `EFFORT`, `REMAINING_WORK`, `BUSINESS_VALUE` and the iteration's capacity, on the board fields. Optional rule `track_sprint_metrics`. |
| **Sprint close** | The one session on the iteration's last working day: Review, then Retrospective, then Refinement, with the carry-over and the next iteration's name. `core/ceremonies/sprint-close.md`. |
| **Ceremony item** | The `Task` on the board that hosts a ceremony — `<iteration name> — Sprint close`, tag `process: ceremony`: cards as comments, minutes attached. Where an agent "attends". |
| **Retro card** | One observation in the retrospective — `went-well`, `went-wrong`, `recurring-impediment` or `improvement` — with the iteration name, its author (role · human/agent) and the items it cites. Agents write them from evidence only. `RULE-RETRO-CARDS`. |
| **Carry-over** | The one decision every open item receives at the sprint close: carry, return or remove — recorded on the item with its reason. `RULE-CARRY-OVER`. |
| **Iteration name** | The name rendered from `cadence.iteration_name_pattern` — `Sprint 02 26 Q1 <product>` by default — on the board, the minutes and the digest. `RULE-ITERATION-NAMING`; `automation/scripts/iteration_name.py`. |
